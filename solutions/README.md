# 選用的知識應用

部門知識的主要成果已在 `knowledge/`。只有使用者要求衍生應用時，才在此建立 `<solution-name>/target.yaml`（用途）、`traceability.yaml`（引用哪些知識）、`artifact/`（實際產品）、`validation.md`（測試及限制）。產品可為 Skill、SOP、Prompt、Script 或知識查詢介面；它們使用既有知識，不是完成蒸餾的必要條件。

須明確引用 Knowledge Release；不能在產品中補造缺少的業務規則。對產品的知識修正先回模型；工具或呈現問題修產品本身。產生 Skill 不會自動安裝或執行真實業務操作。
