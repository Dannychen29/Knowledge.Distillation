# ACTA 訪談操作

改編自 [Militello & Hutton (1998)](https://pubmed.ncbi.nlm.nih.gov/9819578/)，DOI: 10.1080/001401398186108。以下為本專案操作化設計；原研究的訪談評估不直接證明 Codex 執行同樣有效。

## Task diagram

請受訪者用少量階段描述任務，標出需要判斷、容易失敗、不能只照流程的地方，產生任務草圖及 decision hotspots。

## Knowledge audit

依 hotspot 選題，不逐項念問卷：

- 異常辨識：你最早注意什麼？新人會忽略什麼？
- 情境理解：相同表面現象何時代表不同原因？
- 預期：你預測接下來發生什麼？什麼訊號改變預測？
- 可信度：缺資料、資料過期或互相矛盾時怎麼辦？
- 策略：有哪些替代方案，為何捨棄？
- 邊界：何時規則不成立、必須停止或找別人？

## 事件／simulation

從實際困難事件建立時間線：當時知道什麼 → 注意什麼 → 選擇什麼 → 為什麼 → 結果。用「如果線索改變」探查條件；hypothetical case 不能當實測證據。

資源、時間壓力、失敗成本與替代選項可能是 heuristic 的前提。不能把一次成功概括成普遍規則。

## Cognitive demands table

在 evidence/cognitive-demands.md 記錄 task/inference ID、困難點、cues、策略/理由、新手易錯處、案例、邊界、evidence ID。此表是工作稿；確認後回填 canonical objects。

## 回述與反例

回述：「我理解你在 A 條件看 B 線索，因 C 理由選 D；E 時例外。」請受訪者修正並測反例。詢問這是書面規則、共同慣例或個人經驗。確認支持表達忠實性；案例走查支持特定情境，兩者不代表普遍正確。
