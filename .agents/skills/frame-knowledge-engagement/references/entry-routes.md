# 三種材料起點

這是開始擷取證據的路線，不是三套獨立工作流程。持久記在 engagement.source_route；後續收到新材料可以改路線，記錄原因，既有 evidence IDs 不變。department-first/expert-first 是知識切入角度，與 source_route 獨立。

| source_route | 判斷條件 | 第一個動作 | 精準追問 |
| --- | --- | --- | --- |
| guided-interview | 無可用文件或既有訪談成果 | 問工作目標、參與角色、一個真實案例；畫 task diagram | 需要經驗的判斷、線索、失敗情況 |
| document-first | 有作業文件、政策、範本、完成樣本 | 盤點來源版本及欄位，擷取可明示的規則 | 欄位來源、填寫依據、例外、文件與實務差異 |
| map-first | 有訪談後流程圖或既有訪談包 | 解析流程節點、分支、角色與 handoff，回查逐字稿/筆記 | 決策理由、條件、缺失來源、例外與未被訪到的人 |

多種材料並存時，先看最能建立已知事實與流程邊界的材料，再將文件、訪談與案例互相核對。不要硬選單一來源並忽略其他材料。沒有訪談逐字稿的流程圖仍可作 stated/document evidence；圖上未寫的判斷條件保持 unresolved。

範本中的欄位名可直接擷取；空白欄位的填法、資料來源及決策規則不能從格式推導。完成範例可能包含個案值，不能未經核對就提升為通用規則。BA 的流程圖記錄受訪者或分析師的理解，對實際系統動作或決策理由的證明力取決於其來源。

三種路線均先摘要目的與第一個知識密集任務，再建立 run。首輪只問對確定範圍或下一步有影響的問題，不強制提供 PRD、所有文件或系統權限。後續共用同一條 frame → elicit → model → validate → release 路徑。
