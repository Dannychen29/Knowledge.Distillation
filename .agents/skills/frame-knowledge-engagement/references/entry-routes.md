# 材料盤點與啟動

只有兩種新工作情境：沒有現成材料，從訪談開始；已有任意材料，先一併盤點再補訪談。既有 run 則依 state.yaml 續作。這些情境共用 frame → elicit → model → validate → release，不是三套流程。

engagement.source_types 是可複選的材料類型清單，不代表處理優先順序：document（文件／政策）、form（空白或已填表單／範本）、process-map（流程圖）、interview-record（訪談逐字稿／筆記）、case（具體案例）、media（音訊／影片）、observation（操作觀察）。沒有材料時填 `[]`；有新材料時補入並更新 resources。`department-first`／`expert-first` 是知識切入視角，與材料類型獨立。

若有多種材料，先列出每件材料的名稱、版本、產生者、時間、範圍與可追溯位置，再辨認它各自能證明什麼。文件可能明示制度或規則；表單呈現欄位與輸出；流程圖呈現步驟、分支、角色與交接；訪談紀錄可提供判斷理由。用共同任務、步驟或欄位將材料互相對照，標出一致、衝突和缺口，再決定最值得追問的地方。不需固定先讀哪一類；按相關性與證據價值安排閱讀順序。

範本中的欄位名可直接擷取；空白欄位的填法、資料來源及決策規則不能從格式推導。完成範例可能包含個案值，不能未經核對就提升為通用規則。BA 的流程圖記錄受訪者或分析師的理解，對實際系統動作或決策理由的證明力取決於其來源；沒有逐字稿時圖上未寫的條件保持 unresolved。

首輪摘要目的與第一個知識密集任務。零材料時問工作目標、參與角色及一個真實案例；有材料時先整理已知與未知，再問對界定範圍或下一步有影響的問題。不強制使用者先備齊 PRD、全部文件或系統權限。
