# 部門知識庫

這裡是主要交付成果：已確認範圍的部門重要知識。由 publish 將 run 的草稿複製到 `<department>/<domain>/releases/<release_id>/`，並更新 domain 的 index.yaml。先讀 handbook.md 了解規則、判斷、經驗及來源，再讀 coverage.md 查看確認狀態與缺口；各 YAML 保存可維護的模型、案例、確認與檔案指紋。

一個版本只代表 manifest.scope 指定的任務範圍，不代表整個部門知識完整。修正時先回 runs 建新草稿，核對後發布新版本；不直接改已發布手冊。資料流與每個檔案的作用見 [架構說明](../docs/architecture.md)。

此目錄預設可納入 Git，但 commit/push 不是 publish 的一部分。只放適合該 repository 可見範圍的內容；原始材料留 runs。MVP 尚未蒸餾任何真實部門資料，這個 README 只說明用途。
